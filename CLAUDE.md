# Заметки для агентов

## Главный инвариант: соперник не должен иметь возможности читить

Бой строится на одновременном скрытом решении: атакующий выбирает точку
выстрела, защитник — куда откатиться, и **ни один из них не должен узнать выбор
другого до разрешения раунда**. Это не деталь интерфейса, а вся суть игры. Если
защитник может достать `aim_x` до резолва, он уклоняется всегда, и играть не во
что.

Важно: прятать значение в UI бесполезно. Игрок открывает DevTools и смотрит
вкладку Network, `console.log` фреймов вебсокета, `data-*` атрибуты. **Значение
не должно доходить до его браузера вообще.**

### Где инвариант держится

1. **`Battle#state_payload` без аргумента** — версия для бродкаста. Незавершённое
   решение попадает в неё только как `committed: { attacker: true }`, никогда как
   само значение. Именно она уходит в `broadcast_state!`, поэтому общий стрим
   безопасен.
2. **`Battle#state_payload(viewer)`** добавляет секцию `you` с решением **только
   этого** игрока. Вызывать её можно исключительно там, где ответ адресован
   одному конкретному человеку: рендер `battles#show` и `battles#state`
   (ресинк после переподключения). **В бродкаст она не попадает никогда.**
3. **`BattleChannel#subscribed`** отклоняет подписку не-участника боя, а
   `battles#state` — отдаёт `403`. Стрим общий на двоих, так что подписаться на
   чужой бой быть не должно.

Тот же принцип за пределами боя: в `LobbyChannel` личный стрим несёт найденный
бой (адресовано одному), общий — только счётчик ждущих (ничьё). Не складывать в
общий стрим то, что принадлежит конкретному игроку.

### Что ломает инвариант (не делать)

- Добавить `aim_x` / `move_delta` в бродкаст «чтобы было удобнее рисовать».
- Вернуть `broadcasts_refreshes` / Turbo Stream с HTML: HTML собирается из
  состояния, и туда легко утечёт чужой ход. Уход от этого был осознанным.
- Отдавать один и тот же JSON обоим и «фильтровать на клиенте».
- Отдавать `state_payload(viewer)` в любой ответ, который может увидеть второй
  игрок.
- Переносить правила урона или резолва на клиент. Сервер — единственный
  авторитет: он считает попадание, урон и HP. Клиент только рисует то, что уже
  решено.

### Как проверить, что не сломал

Открыть бой в двух независимых сессиях, сделать ход одной стороной и убедиться,
что в браузере соперника нет самого значения:

- фрейм в `/cable` содержит `committed`, но не содержит числа;
- в DOM нет `you` с чужим решением;
- ответ `GET /battles/:id/state` за второго игрока не несёт чужой выбор.

## Игрок в бою заперт в бою

`ApplicationController#hold_player_in_battle` уводит на текущий бой **любую**
страницу, пока бой не закончен: нельзя записаться в лобби на второй бой и
нельзя разгуливать по приложению.

Страж намеренно включён по умолчанию для всех контроллеров, а не подключается
вручную. Новая страница попадает под него сама, без того чтобы кто-то о нём
вспомнил. Поэтому:

- **не добавлять `skip_before_action :hold_player_in_battle`** без веской
  причины — это дыра, через которую страница выпадает из правила;
- исключения определяются **путём**, а не именем контроллера: всё, что лежит
  под `battle_path(battle)`, работает (сама страница, `state`, ходы). Новый
  эндпоинт боя, добавленный под этим префиксом, заработает автоматически;
- Devise исключён отдельно, иначе из аккаунта нельзя было бы выйти;
- JSON-запросы получают `409` с `battleId`, а не редирект, — `fetch` за
  редиректом не пойдёт.

`Battle#accept!` вдобавок вычищает обоих игроков из очереди лобби: подбор своё
уже удалил, а вызов со страницы дуэлей — нет.

## Другие инварианты

**В SVG (`app/views/battles/_field.html.erb`) нет серверных динамических
значений.** Все позиции танков, дуги и снаряды ставит `battle_controller.js` из
`data-*` на обёртке. Как только в сцену попадёт `<%= %>` с позицией, любая
перерисовка страницы будет рвать анимацию посередине.

**Страница боя запрашивается один раз.** Дальше состояние ходит JSON'ом через
`BattleChannel`, все панели уже отрендерены в HTML и переключаются на клиенте.
Не добавлять редиректы и рендеры HTML в игровой цикл.

**Резолв раунда идёт под `with_lock`** — оба игрока могут нажать одновременно.

**Время хода проверяет сервер, а не браузер.** `POST /battles/:id/expire` — это
просьба посмотреть на часы, а не утверждение «время вышло»:
`Battle#resolve_if_expired!` сам сверяется с `deadline_at`. Не делать эндпоинт,
который резолвит ход по слову клиента, — иначе соперника можно лишать хода
досрочно. По той же причине `deadline_at` не приходит на клиент: шлём
`turnEndsIn` (сколько осталось секунд), чтобы не зависеть от часов устройства.

## Как проверять изменения через chrome-devtools

Игра — это два игрока, вебсокет и анимации, поэтому «код скомпилировался»
здесь ничего не доказывает. Ниже то, обо что тут реально спотыкаешься.

### Готовить состояние — через `rails runner`, а не кликами

Дойти кликами до нужного хода долго и хрупко. Ставь позицию прямо:

```bash
export PATH="$HOME/.rbenv/shims:$PATH"
bin/rails runner '
  b = Battle.find(N)
  b.submit_aim!(b.attacker, b.position_for(b.defender))
  puts "RESULT ход=#{b.turn_number}"
' 2>&1 | grep "^RESULT"
```

Префикс `RESULT` и `grep` обязательны: shell подмешивает свой мусор
(`compinit`, `DEBUGGER: can not load newer irb`), и без фильтра вывод не
читается.

**Осторожно с боями между теми же двумя персонажами:** живой бой на пару всего
один, а активный бой запирает игрока (см. раздел про стража) — тестовые бои
удобно сносить через `Battle.where.not(status: :finished).destroy_all` перед
каждым сценарием. И **убирай за собой** в конце: лишние бои и записи в очереди
ломают следующий прогон.

### Два игрока — это два `isolatedContext`

Cookies общие внутри контекста и изолированы между. Один игрок — один контекст:

```
new_page(url: ".../users/sign_in", isolatedContext: "p1")
new_page(url: ".../users/sign_in", isolatedContext: "p2")
```

Переключаться между вкладками — `select_page(pageId)`; `list_pages` показывает,
какая выбрана и в каком контексте.

### Читать состояние из контроллера, а не со скриншота

`window.Stimulus` выставлен в `controllers/application.js`, так что до любого
Stimulus-контроллера можно дотянуться и прочитать его внутренности — это на
порядок надёжнее разглядывания картинки:

```js
const el = document.querySelector('[data-controller="battle"]')
const c = window.Stimulus.getControllerForElementAndIdentifier(el, 'battle')
return { turn: c.state.turnNumber, role: c.role(), outOfTime: c.outOfTime }
```

**Скриншоты не ловят короткие анимации.** Задержка MCP больше, чем живёт
всплывающий урон (3 с), — снимок всегда приходит к пустому месту. Проверяй
координаты и текст в DOM, а если нужно увидеть глазами — заморозь анимацию
(например, сдвинув `damageToken`, который её отменяет).

### Навигация убивает контекст выполнения

Клик, ведущий на другую страницу, обрывает `evaluate_script` ошибкой
`Execution context was destroyed`. Это не сбой — просто **читай результат
следующим вызовом**, а не в том же. Логин, редирект стража, авто-переход в бой
из лобби — все ведут себя так.

### Websocket: как сымитировать обрыв

```js
c.consumer.connection.close({ allowReconnect: false })  // положить
c.consumer.connection.open()                            // поднять
```

Между ними меняй состояние на сервере через `rails runner` — так проверяется,
что клиент догоняет пропущенное. Помни, что `connected` считаем сами
(`socketEverConnected`), а не по флагу `reconnected`.

### curl и CSRF: лучше не надо

Токен со страницы, которая отвечает редиректом, вытащить нельзя — тела нет, и
запрос падает с `422 Can't verify CSRF token authenticity`. Для POST'ов проще
дёрнуть `fetch` прямо из авторизованной страницы, где `meta[name=csrf-token]`
настоящий. Для GET'ов curl нормален.

### Перезапуск сервера обязателен

- **после миграции** — иначе кеш схемы старый и новая колонка приходит сырой
  строкой (`undefined method '-' for "2026-08-09...":String`);
- **после правки локалей** — они читаются на старте.

### В конце — консоль

`list_console_messages(types: ["error", "warn"])`. Пустой список входит в
определение «работает»; ошибку в консоли легко не заметить, если смотреть
только на разметку.

## Окружение

Ruby 3.2.2 из rbenv собран под x86_64 и работает через Rosetta, компилятор
таргетит arm64 — нативные гемы ломаются несовпадением архитектур. Подробности и
способ починки в README, раздел «Заметка про окружение».

Перед запуском: `export PATH="$HOME/.rbenv/shims:$PATH"`.
